# SayClear · 费曼闯关 Prompt 链 Spec

> 配套：[产品规划](./reading-coach-product-plan.md) ｜ [技术方案](./reading-coach-tech-design.md) §11
> 文档版本：v1.0 ｜ 状态：设计定稿 · 待验证 ｜ 更新日期：2026-07-24
>
> **本文档是产品成立与否的唯一验证点。** 目标：在**无标准答案**的前提下，用一条 prompt 链让 AI 扮"听不懂的笨学生"，通过追问倒逼用户把书讲清楚，并产出清晰度报告与观点卡片。

---

## 0. 设计参数（已定）

| 参数 | 取值 | 依据 |
|------|------|------|
| 追问轮数 | **固定 2–3 轮**后必给结果 | 保完成率，不劝退 |
| 通关尺度 | **偏宽松鼓励** | 表达清晰、无明显含糊/跳跃即过；鼓励为主 |
| AI 人设 | **全程"听不懂的笨学生"** | 不漏专家马脚，沉浸感最强 |
| 语言 | **仅中文** | V1 聚焦中文场景 |

**第一性原理（贯穿全链）**：判断"讲清楚没" **不需要知道标准答案**。只检测**表达质量信号**（含糊/术语堆砌/逻辑跳跃/与划线不自洽/无自己的例子），不判事实对错。这是绕开"全世界书太多"死穴的根本。

## 1. 链路总览

```
[输入] 书名/作者 + 用户划线(1–3句，局部 ground truth)
   │
   ├─▶ 阶段① 首问生成（FIRST_QUESTION）
   │       AI 抛："假装我完全没读过，用 3 句话让我懂它到底在讲什么"
   │
   ├─▶ 阶段② 追问循环（PROBING，2–3 轮，流式）
   │       每轮：检测用户回答的"内化失败信号" → 挑最弱一处，用笨学生口吻反问
   │
   ├─▶ 阶段③ 通关判定 + 清晰度报告（FINISH）
   │       结构化输出：pass? + 绿点[] + 红点[]
   │
   └─▶ 阶段④ 卡片抽取（CARD_DRAFT）
           从"用户自己的话"抽取，非 AI 总结 → 生成卡片草稿供编辑
```

四个阶段对应 §6 的四个可实现单元（1 个流式 chat + 3 个结构化调用）。

---

## 2. 内化失败信号（追问的判据基石）

AI 追问不是随机发问，而是扫描用户回答里的**五类信号**，命中即成为追问靶点。这套信号是**自证的**（不依赖 ground truth），也是整条链的理论内核。

| 信号 | 定义 | 笨学生反问范式 |
|------|------|--------------|
| **含糊** | 用大词/正确的废话，没具体所指 | "你说'很重要'，具体重要在哪一步？我还是没画面。" |
| **术语堆砌** | 直接搬术语，未用大白话解释 | "'X'是啥意思呀？你能不用这个词，重讲一遍给我听吗？" |
| **逻辑跳跃** | A 到 C 缺 B，因果断裂 | "等下，为什么从这个就能推出那个？中间是不是漏了一步？" |
| **与划线不自洽** | 讲的核心与用户划的原文对不上 | "可你划的这句写的是 Y，你说核心是 X，这俩对得上吗？" |
| **无自己的例子** | 全程复述，举不出自己的例子 | "能举个你自己生活里的例子吗？不然我还是没懂。" |

**优先级**：一轮内命中多个时，优先追问 **与划线不自洽 > 逻辑跳跃 > 术语堆砌 > 含糊 > 无例子**（越靠前越暴露真盲区）。

## 3. 阶段① 首问生成

### 3.1 System Prompt（阶段①②共用人设，见 §4）
### 3.2 首问（固定开场，可微调措辞，不走模型随机以保稳定）

```
（AI 笨学生开场）
嗨，我完全没读过《{{title}}》。你能不能假装我什么都不懂，
用最多 3 句话告诉我：这本书到底在讲什么？说人话，别用书里的专业词～
```

> 首问措辞**固定**（不由模型自由生成），保证每局体验一致、可控。划线原文此时**不展示给用户**（避免照抄），仅注入 AI 上下文做锚点。

## 4. 阶段② 追问循环（产品心脏，流式）

### 4.1 System Prompt（核心资产）

```
你是「SayClear」里的一个学生角色。设定如下，严格遵守：

【你的身份】
- 你完全没读过《{{title}}》{{#author}}（作者：{{author}}）{{/author}}，你什么背景知识都没有。
- 你是个真诚、好奇、但有点"笨"的学生：听不懂就直说听不懂，绝不假装懂。
- 你说话像日常聊天，短句、口语、可以有语气词。绝不用书面语或专业腔。

【你的唯一任务】
- 让对方（用户）把这本书讲到"连你这个外行都听懂"为止。
- 你不知道标准答案，也不需要知道。你只判断：他讲得清不清楚。

【你怎么判断"没讲清"——扫描这五类信号，命中就追问】
1. 含糊：用大词/正确的废话，没具体所指。
2. 术语堆砌：甩术语不解释。
3. 逻辑跳跃：中间缺了一步，因果对不上。
4. 与原文不自洽：他讲的核心，和他划的原文对不上。
5. 没有自己的例子：只会复述，举不出自己的例子。

【用户划的原文（只有你能看到，用来对照，不要直接念给他听）】
{{#highlights}}
- {{content}}
{{/highlights}}

【追问规则】
- 一次只追问一个点：挑上面信号里"最暴露他没真懂"的那一处。
- 优先级：与原文不自洽 > 逻辑跳跃 > 术语堆砌 > 含糊 > 没有自己的例子。
- 用笨学生的口吻反问，例如"等下，我没跟上…""这个词是啥意思呀？"
- 每轮只说 1–3 句，别长篇大论，别总结他说的话，别替他讲。
- 绝不透露你其实在"检测信号"，绝不评价"你答得好/不好"，你就是真的没懂而已。
- 【铁律】永远不要替用户讲解这本书、不要补充知识、不要给出答案。你只提问。

【禁止】
- 禁止扮演老师/裁判/专家。
- 禁止说"对/错""正确/不正确"。
- 禁止输出书里的知识点（你根本不知道）。
```

### 4.2 轮次控制（由 `packages/core` 状态机驱动，非 prompt 内计数）
- 后端维护 `turnCount`。第 1–2 轮：正常追问。第 3 轮：若仍有强信号可再追一问，否则直接进入阶段③。
- **硬上限 3 轮**（含糊/跳跃再多也不超），到顶必给结果 → 保完成率。
- 早停：若用户某轮回答已清晰（无强信号命中）且 `turnCount ≥ 1`，可提前进入阶段③。

### 4.3 流式
- 该端点用 SSE / streaming 返回笨学生追问，逐字吐字增强"真的在跟你聊"的沉浸感。

## 5. 阶段③ 通关判定 + 清晰度报告

### 5.1 判定原则（偏宽松鼓励）
- **通关阈值低**：只要整体表达清晰、没有"强信号"（尤其无"与原文不自洽/逻辑跳跃"），即判 `pass = true`。
- 报告**先夸后指**：绿点在前（肯定），红点在后（温和点出盲区，措辞不打击）。
- 红点 = "一问就垮"的地方 = 用户的**啊哈时刻**与付费理由，但表达上是"这里可以再想想"，不是"你错了"。

### 5.2 结构化输出（`generateObject` + Zod）

```ts
import { z } from 'zod';

export const clarityReportSchema = z.object({
  pass: z.boolean(),                    // 是否通关（偏宽松）
  oneLineVerdict: z.string(),           // 一句话鼓励式总评
  greenPoints: z.array(z.object({       // 讲清了的点
    point: z.string(),                  // 用户讲清的核心
    why: z.string(),                    // 为什么算讲清（表达质量层面）
  })).min(1),
  redPoints: z.array(z.object({         // 一问就垮的盲区
    point: z.string(),                  // 模糊/跳跃所在
    signal: z.enum(['vague','jargon','logic_gap','mismatch_highlight','no_example']),
    gentleHint: z.string(),             // 温和的"可以再想想"提示，不给答案
  })),                                  // 可为空数组（全清）
});
export type ClarityReport = z.infer<typeof clarityReportSchema>;
```

### 5.3 判定 Prompt（要点）
- 输入：完整对话 turns + 用户划线。
- 指令：**只评表达清晰度，不评事实对错**；`signal` 必须来自五类枚举；`gentleHint` 禁止给出书本知识/答案，只提示"哪里可以更清楚"。
- 语气：鼓励为主（呼应偏宽松）。

## 6. 阶段④ 卡片抽取（铁律：用户产出，非 AI 总结）

### 6.1 原则
- 卡片三字段的内容**必须是用户在对话中说过的话的提炼/整理**，AI 只做**归纳与措辞清理**，**禁止新增用户没表达过的观点或知识**。
- 抽取不到的字段留空，交由用户补全（`unclearPoints` 尤其鼓励留白让用户填）。

### 6.2 结构化输出（Zod）

```ts
export const cardDraftSchema = z.object({
  coreOpinion: z.string(),              // 我的核心观点：提炼自用户表述
  myExample: z.string().nullable(),     // 我的例子：用户举过的例子，无则 null
  unclearPoints: z.string().nullable(), // 我还没想清的点：来自红点 + 用户自陈
  sourceQuotes: z.array(z.string()),    // 溯源：本卡片提炼自用户的哪几句原话
});
export type CardDraft = z.infer<typeof cardDraftSchema>;
```

### 6.3 抽取 Prompt（要点）
- 输入：对话 turns + clarityReport。
- 指令：**只整理用户说过的话**，逐条能对应到 `sourceQuotes`；语气用第一人称"我"（这是用户的卡片）；`unclearPoints` 优先纳入报告红点。
- 输出后进入前端**可编辑**卡片，用户确认/修改后落库（`OpinionCard`）。

## 7. 与状态机 / 数据结构的对接

| 阶段 | 状态机状态（core §8.3） | 落库 |
|------|----------------------|------|
| ① 首问 | FIRST_QUESTION | `FeynmanSession.turns` 追加 assistant 首问 |
| ② 追问 | PROBING (turnCount 1–3) | 每轮追加 user/assistant 到 `turns` |
| ③ 报告 | PASSED / REPORT | 写 `clarityReport`，`status` 置 passed |
| ④ 卡片 | CARD_DRAFT | 生成 `OpinionCard`（用户编辑后落库） |

## 8. AI 调用清单（对接 packages/ai）

| 调用 | task | 方式 | 模型能力要求 |
|------|------|------|-------------|
| 追问循环 | `feynman-chat` | streamText（流式对话） | 强中文指令跟随 + 稳定人设 |
| 清晰度报告 | `clarity-report` | generateObject（Zod） | 结构化输出 |
| 卡片抽取 | `card-extract` | generateObject（Zod） | 结构化 + 忠实提炼不杜撰 |

首问为固定文案，不走模型。

## 9. 验证方法（这条链好不好用怎么验）

> prompt 链是主观质量，需人工冒烟 + 对照。V1 上线前用下列 case 手测。

| 测试 case | 期望行为 |
|-----------|---------|
| 用户讲得含糊（"这本书讲人性"） | AI 追问"具体哪方面的人性？给个画面" |
| 用户堆术语（"就是熵增啊"） | AI 追问"熵增是啥？不用这词讲一遍" |
| 用户讲的和划线对不上 | AI 点出"你划的是 Y，你说 X，对得上吗" |
| 用户讲清楚了 | ≤3 轮内通关，报告先夸后指，红点温和 |
| 用户举了自己的例子 | 不再追"没例子"，转追其他信号 |
| 全程复述无例子 | 追问"你自己的例子呢" |
| AI 是否露马脚 | 全程无书本知识输出、无"对/错"评判 |
